Technical & Self-Hosting Reference

Everything here is intended for self-hosters, terminal users, and developers: running the standalone web server, deploying with Docker as a Progressive Web App (PWA), CLI flags, environment variables, synkban.toml, and on-disk storage internals.

Using the Desktop App? You don't need any of this — head to the everyday User Guide.

Standalone Web Server (Web Mode)

Synkban compiles into a single self-contained Rust binary with all frontend assets embedded. Run it directly from a terminal (or build from source with ./build.sh):

./synkban

Open http://localhost:8080 in your browser.

Security note: Web Mode has no built-in authentication (single-user design). Run it on localhost, over a private network (such as Tailscale), or behind an authenticating reverse proxy.

Docker & Mobile / Desktop PWA

Official multi-architecture (linux/amd64, linux/arm64) container images are published to ghcr.io/waschmittel/synkban:

docker run -d \
  --name synkban \
  -p 127.0.0.1:8080:8080 \
  -e DATA_DIR=/data \
  -v /path/on/host/data:/data \
  -v /path/on/host/config:/app/config \
  ghcr.io/waschmittel/synkban:latest
Permissions: The container runs as non-root user app (UID 10001). Ensure mounted host directories are writable by UID 10001 (for example, chown -R 10001:10001 /path/on/host/data /path/on/host/config).

Readable Mirror (synkban export)

Generates an incremental, one-way, browser-browseable HTML mirror of saved boards (active and archived), lists, cards, and attachments:

<output-dir>/
├── README.md
├── index.html                   # Master-detail explorer (file:// & http(s)://)
├── style.css                    # Shared light/dark/print stylesheet
├── .synkban-mirror.json         # Manifest of owned paths & incremental hashes
└── boards/{board-id}/cards/{card-id}/
    ├── card.html                # Pure semantic HTML (../../../../style.css)
    └── attachments/             # Simple unique names verbatim, else {att-id}.{ext}

In Desktop Mode, configure the folder and schedule (off | daily | weekly) in Settings → Readable mirror. In Web Mode / Docker, run the CLI subcommand from cron or a backup hook:

./synkban export /path/to/mirror --data-dir /path/to/data
# Inside Docker:
docker exec synkban /usr/local/bin/synkban export /mirror

Unchanged cards and attachments are skipped; only manifest-tracked paths are pruned; corrupt source JSON aborts the run before touching the mirror; and overlapping DATA_DIR or SYNKBAN_CONFIG_DIR paths are refused. If hosting index.html behind a reverse proxy, allow same-origin framing (X-Frame-Options: SAMEORIGIN).

Directories & synkban.toml

1. Data Directory (Sync Across Devices)

<DATA_DIR>/
└── boards/
    └── {board-id}/
        ├── board.json
        ├── lists/{list-id}/
        │   ├── list.json
        │   └── cards/{card-id}.json
        ├── archived_cards/{card-id}.json
        └── attachments/{card-id}/
            ├── {att-id}
            ├── {att-id}_thumb
            └── {att-id}.json

Data Directory resolution order (highest priority wins):

  1. --data-dir <path> CLI flag
  2. DATA_DIR environment variable
  3. data_dir in ~/.config/synkban/synkban.toml
  4. Default: ~/.config/synkban/data/ (%USERPROFILE%\.config\synkban\data\ on Windows)

2. Config Directory (Keep Local to Each Machine)

Stored in ~/.config/synkban/ (or SYNKBAN_CONFIG_DIR) and intentionally excluded from synced board data:

  • synkban.toml — persisted Settings (editable when Synkban is stopped):
data_dir = "/home/me/Sync/synkban"
startup_view = "last"      # "overview" (default) | "last"
theme = "system"           # "system" (default) | "light" | "dark"
last_board_id = "..."      # maintained automatically
# Desktop Mode only:
mirror_dir = "/home/me/Sync/synkban-mirror"
mirror_schedule = "daily"  # "off" (default) | "daily" | "weekly"
  • draft.json — the single local crash-recovery Draft for the currently open card.
  • mirror-state.json — Desktop Mode readable-mirror status (last_succeeded_at, last_attempt_at, last_error, cards_mirrored).

Sync & Storage Internals

  • Atomic file writes: JSON updates write to a temporary file beside the target and atomically rename over it, preventing half-written JSON during crashes or sync scans.
  • Sidecar attachments: Each upload creates raw bytes ({att-id}), an optional JPEG thumbnail ({att-id}_thumb ≤ 400 px), and metadata sidecar ({att-id}.json) outside the card JSON so uploads never conflict with concurrent card edits.
  • 15-second change polling: The UI polls GET /api/changes every 15 seconds and refreshes only changed boards while keeping open forms and keyboard focus intact.
  • 5-minute attachment GC grace window: Startup cleanup ignores partial/orphaned attachment files newer than 5 minutes so active syncs are never mistaken for leftovers.
  • Desktop local auth: Desktop Mode spawns the Rust binary on a random 127.0.0.1 port with a per-launch UUID token so other local apps cannot reach your boards.
  • Version alignment: Keep all synced devices on the same Synkban version so newer card features (tables, matrices, Lua blocks, inline images) render consistently everywhere.
