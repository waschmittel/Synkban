# Runnable Lua blocks run in a sandboxed WebAssembly worker with persisted output

## Decision

Card descriptions support a dedicated `lua_block` node (`schema.json`: `content: "text*"`, `group: "block"`, `marks: ""`, `code: true`, `attrs: { output, error, ran_hash }`) intended for **short calculations, scratchpads, and note helpers** — not a full IDE or external I/O runtime:

- **Native ProseMirror NodeView (`luaBlock.ts`, `app.css`):** `createLuaBlockView` uses `<pre class="lua-block-pre lua-block-code">` directly as `contentDOM` under `<div class="lua-block">` (with no inner `<code>` wrapper), restricts `ignoreMutation` strictly to mutations inside the non-editable `header` and `result` elements, and moves focus/selection into the block on `header` `mousedown` when outside. Keeping `<pre>` as `contentDOM` (with Notes Mode's single-line measure rule scoped to `.ProseMirror > pre`) ensures `<pre>` padding clicks, multi-line selection, focus restoration, undo/redo, copy/paste, IME, `Tab` indentation, `Accel+S`, and `focusTrap` work natively.
- **Schema, GapCursor & Text Styles (`schema.ts`, `proseEditor.ts`, `editorMenu.ts`):** `luaBlockSpec` sets `selectable: false` and `"lua_block"` is listed in `GAP_CURSOR_BLOCKS` (`createGapCursor: true`) so arrow navigation and editor padding clicks place a `GapCursor` above or below leading/trailing blocks. `TEXT_STYLES` uses multi-block `isTextStyleActive` and `setTextStyle` wrapped in `MenuItem` so `TypeDropdown` and the `Accel+K` menu share identical logic: inserting a block at a `GapCursor`, merging multiple selected textblocks into one multi-line `code_block` or `lua_block`, and splitting multi-line blocks back into separate paragraphs or headings.
- **Syntax highlighting & autocomplete (`luaSyntax.ts`, `proseEditor.ts`):** Syntax highlighting renders view-only `Decoration.inline` spans (`tokenizeLua`). Autocompletion renders a caret-anchored popup over keywords, sandboxed stdlib modules (`math.`, `string.`, `table.`, `utf8.`, `os.`), and identifiers declared in the block, handles keys via ProseMirror `props.handleKeyDown` in `luaCompletionPlugin`, and is registered via `...luaPlugins()` *before* `tableMenuKeymap` in `proseEditor.ts` so `Escape` closes the popup and stops propagation before `tableMenuKeymap`'s `Escape` swallow handler runs. `Tab` accepts the top suggestion, while `Enter` only accepts after explicit `ArrowUp`/`ArrowDown` selection (otherwise passing through as a normal newline); completion is suppressed right after declaration keywords (`local`, `function`, `for`) and on exact keywords, excludes the half-typed identifier at `caretOffset` when scraping locals, and closes on non-`docChanged` cursor moves or `focusout`.
- **Sandboxed Lua 5.4 worker (`luaEval.ts`, `luaWorker.ts`, `luaRunner.ts`):** Evaluation runs client-side in a Web Worker using `wasmoon` (Lua 5.4 WASM, served as `application/wasm` in `backend/src/lib.rs`) with `injectObjects: false`, a 16 MB allocation limit, stripped `io`/`package`/`require`/`debug`/`dofile`/`loadfile`, read-only time/date `os` helpers, text-only `load`, an 8 KB output cap, an instruction-count hook, and a 1500 ms `worker.terminate()` hard timeout. Blocks **never auto-run on open**; users invoke them explicitly with **Run** or `Mod-Enter` (`Shift-Enter` exits below).
- **Persisted deterministic attributes:** Results are stored in `{ output, error, ran_hash }` (`ran_hash` is a 32-bit FNV-1a hex digest over UTF-16 code units, matching `backend/src/pdf.rs::fnv1a_32_hex`) with no timestamps or timings. Editing code flips the UI status (and PDF header) to **Outdated** until re-run; **Clear** resets all three attributes to `null`.
- **Entry points & block escape (`luaBlock.ts`, `blockEscape.ts`):** `TEXT_STYLES` (`Lua block`, `Accel+K` → `E`, toolbar dropdown) and `luaFencePlugin()` (`appendTransaction` upgrading ```` ```lua ```` immediately when typed while preserving `prosemirror-history` and consuming an optional single trailing `Space` or `Enter`); `Backspace` on an empty block returns to a paragraph and `Shift-Enter` exits below.

## Why

- **Right-sized for card snippets:** Native ProseMirror avoids CodeMirror's ~100+ KB dependency and fragile dual-history/focus/key bridging while still providing syntax colours and signature-hinted autocomplete.
- **Clean security & cross-platform builds:** Running WASM in a sandboxed browser Worker adds zero C toolchain dependencies to the Rust macOS/Linux/Windows/Docker builds, works offline on unsaved edits, and kills runaway loops cleanly via `worker.terminate()`.
- **Offline PDF/A-2u & history diffs:** Because PDF export ([ADR-0012](0012-pdf-a-export.md)) only renders saved card data, persisting `{ output, error, ran_hash }` lets the Rust backend include evaluated results in PDFs (`pdf.rs`) and `diff.ts` show result changes without running Lua server-side. Omitting `ran_at`/`duration_ms` guarantees re-running deterministic code never dirties a card.

## Considered and rejected

- **Embedding CodeMirror 6 in the NodeView** — overkill for short card scratchpads; requires synchronizing document diffs, `prosemirror-history`, boundary arrow/Backspace navigation, and overlay key ownership (`Escape`, `Accel+K`, `Accel+S`).
- **Backend Rust `mlua`** — requires C compilation across all three release platforms and manual instruction-hook/memory sandboxing per request, and fails when offline or editing unsaved content.
- **Extending `code_block` with `attrs.lang`** — clutters plain `code_block` with evaluation attributes (`output`, `error`, `ran_hash`); both options are schema changes anyway (`schema.rs`).
- **Ephemeral output (not persisted)** — would omit computed results from server-side PDF/A-2u exports and card history diffs.
